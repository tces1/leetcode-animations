215. 数组中的第 K 个最大元素 · 快速选择动画

每轮四步
① 取出 [lo, hi]
外面的格子本轮不看。第 k 大对应升序下标 target = n − k，只要这个下标落进等于段。
② 藏起 pivot
在区间里随机抽一个下标 r，和 hi 交换。代码里的 privot 就是这个基准，扫描时先不去动它。
③ 三路划分
扫描下标 k 从 lo 走到 hi − 1。< 就经 j 转到 i 并 i++, j++；== 只进 j；> 留下。
④ 归位并对账
把 hi 上的基准换到 j。若 i ≤ target ≤ j 就返回；j < target 则 lo = j + 1，否则 hi = j − 1。
为什么不直接 sort？全排序要确定每个名次，O(n log n)。这里每轮只处理取出的 [lo, hi]，等于段可以一次吃掉所有重复基准，期望 O(n)。扫描中的不变量：[lo, i) 都 < pivot，[i, j) 都 == pivot，[j, k) 都 > pivot，hi 藏着基准。循环变量 k 和题目的 k 同名，动画里扫描指针标成 k，第 k 大仍看输入框。
每轮四步
① 当前列表
递归处理 _nums。left_num 是已经确定「比当前段更大」的个数。要找的是降序第 k 名，当前段里的下标 idx = k − 1 − left_num。
② 抽 pivot
pivot = random.choice(_nums)，不交换、不藏到末尾，原列表保持不动。
③ 开三个数组
扫一遍：> pivot 进 left（更大，降序靠前），== 进 mid，< 进 right（更小，降序靠后）。
④ 对账后递归
idx < len(left) 则只看 left；落在 mid 就返回 pivot；否则看 right，并把 left_num 加上 left+mid 的长度。
和方案①差在哪？两边都是三路快选，期望都是 O(n)，不是更快的渐近复杂度。差别主要是：①按升序下标 n−k 在原数组里交换；②按降序名次 k−1 每轮 append 出新列表再递归。Python 里列表 append 走 C 实现，比一堆下标交换更吃香，所以提交往往更快；代价是额外 O(n) 空间。Java 里频繁 new ArrayList 就不一定更快。
示例： 经典 k=2 大量重复 k=4 全相等 逆序 已有序 · 最大值 短数组 k=1
